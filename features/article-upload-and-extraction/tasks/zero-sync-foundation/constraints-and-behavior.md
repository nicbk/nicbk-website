# Constraints and Behavior: Zero Sync Foundation

Which of the feature's acceptance criteria
([../../constraints-and-behavior.md](../../constraints-and-behavior.md)) this
task satisfies.

## Satisfied here

**From "Sync engine and services":**

- The `zero-cache` service exists in `docker-compose.yml`, pinned to a version
  tag, on `app-internal`, in single-node mode.
- `ZERO_UPSTREAM_DB` / `ZERO_CVR_DB` / `ZERO_CHANGE_DB` point at separate
  databases **inside the one shared Postgres service**; `ZERO_REPLICA_FILE` is
  on a persisted volume; the upstream connection is direct, not pooled.
- The new Zero variables are declared in `src/env.ts`'s Zod schema, documented
  in `.env.example`, and are **server-only, never `VITE_`-prefixed**.

**From "Schema":**

- `articles` and `upload_jobs` are declared in Drizzle and migrated exactly as
  their schema docs specify — including `authors_search` (`generated always as
  ... stored`) and its `pg_trgm` GIN index, `status` defaulting to `'pending'`,
  `extraction_status` defaulting to `'pending'`, `upload_jobs.status`
  defaulting to `'processing'`, and `pdf_object_key` as `not null` on both.
- Every `user_id` FK is `ON DELETE CASCADE`; `upload_jobs.article_id` is a
  nullable `ON DELETE CASCADE` FK to `articles`.
- Primary keys are client-generated UUIDv7, except `upload_jobs.id`, which
  defaults to Postgres's native `uuidv7()`.
- The migration is **additive only** (expand phase).
- `zero/schema.ts` is generated by `drizzle-zero` and guarded by a CI drift
  check; a Drizzle schema change without regeneration fails the build.
- The `pgboss` schema is excluded from the publication Zero replicates.

**From "Authorization and data isolation":**

- `/query` and `/mutate` exist on the app server. Every synced query is scoped
  by the `user_id` of a **server-derived context** resolved from the Better Auth
  session — never from client-supplied arguments.
- A request with no valid session returns nothing. A request whose arguments
  name another user's `user_id` or row IDs returns nothing.

**From "Cross-cutting quality":**

- The stack runs under `docker compose up` with the new service, and the app
  still runs via `npm run dev` and the production Nitro server.
- CI passes, including the new `zero/schema.ts` drift check.

## Explicitly not satisfied here

- **Nothing user-visible.** No route, no page, no component, no client-side
  Zero provider. Every criterion under "Routes and shell", "Upload flow",
  "Upload status indicator", and "Extraction pipeline" belongs to a later task.
- **`citation_edges`** — task 5, with the enrichment that gives it meaning.
- **`/mutate` has no registered mutators.** The endpoint is real and
  authorized; it exposes nothing to call, because nothing in this feature writes
  from the browser.
- **Garage, pg-boss, GROBID** — tasks 3, 4, and 5.

## Exit state

A signed-in user's synced query returns that user's `articles` and
`upload_jobs` rows and nothing else, proven by integration tests against a real
Postgres with a second user's rows present. `docker compose up` brings the
stack up with zero-cache healthy and replicating. No page renders any of it.
