# Task: Marking From the Selection

**Second of two**, and the one that closes the feature. The floating control
over a selection gains the reader's text tools.

## What it does

- **Offers highlight, underline, strikeout and squiggly beside `copy`**, on the
  control that already floats over a selection.
- **Marks the selected passage** when one is chosen — one mark per page it
  covers — through the annotation capability, with the chosen tool's own
  defaults.
- **Involves no tool mode**, which is the whole point: picking a tool from the
  toolbar clears the selection, so a touch reader has no way to hold both at
  once. Nothing here changes modes, so nothing clears anything.

## What it does not do

- **No new tools.** These are four of #9's twelve, reached from a second place.
- **No change to the toolbar.** Picking a text tool there and dragging still
  marks, exactly as it does today.
- **No colour picker.** Deferred by `reader-annotation.md` and still deferred;
  each action uses its tool's defaults.

## Why it is a task of its own

Because it is design rather than repair. Task 1 is judged against numbers that
already exist; this is judged against how it feels to use and how it holds at a
realistic width — and against `reader-annotation.md`'s own warning that two
entry points to one outcome is normally one too many.

## Exit state

A reader on a phone presses a word, drags the handles over the sentence they
want, taps *highlight*, and the sentence is highlighted — the path that has been
missing since the reader learned to select by touch.
