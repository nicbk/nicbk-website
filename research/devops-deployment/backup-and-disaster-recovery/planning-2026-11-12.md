# Backup and Disaster Recovery: Planning Decisions of 2026-11-12

Decided 2026-11-12, while #32
([features/backups-you-can-relaunch-from](../../../features/backups-you-can-relaunch-from/description.md))
was planned. The revision ([revision-2026-10-14.md](./revision-2026-10-14.md))
left two choices to planning ("whatever makes the most sense"), and the user
decided two more on the spec. The sources and the research behind each are in
the feature's [research.md](../../../features/backups-you-can-relaunch-from/research.md).

## Delegated to planning

| # | Decision | Why |
|---|---|---|
| BK3 | **Backblaze B2, through its S3 API** | It is the only candidate where a compromised node cannot destroy history: the node's key lacks `deleteFiles`, so deletes only hide files, and a lifecycle rule erases hidden files later. R2 has no versioning, and its bucket locks would break `restic prune`. At 50 GB, B2 is about $0.35 a month, and a monthly full drill fits in its free egress (3× stored). |
| BK11 | **Archive the images** in the same repository, as separate `images` snapshots, only when the set of digests changes | A relaunch is when a registry outage, a rate limit or a deleted tag hurts most. About 840 MB compressed for the third-party images, cents a month. |

## Decided with the user

The user's words: [answers](../../requests/2026-10-14/answers-2026-11-12.md#answers-to-p32-1-and-p32-2-as-written).

| # | Decision |
|---|---|
| P32-1 | **Hidden files stay 30 days** before the lifecycle rule erases them, instead of BK8's 1 ("keep only the last version"): the window in which history "deleted" by a compromised node can be recovered. |
| P32-2 | **A size ceiling**: the repository stays within 10× the largest checkpoint of the last 30 days, never below a 5 GiB floor. The oldest checkpoints go first, never one younger than 30 days, and the operator is told whenever it binds. With no checkpoint in the last 30 days it removes nothing. **The one-year limit (`--keep-monthly 12`) stays until zero-access encryption (#39+), which then removes it**, leaving the ceiling as the only limit on history. |

## Implementation choices made in planning

These do not change the decision; each is explained where it is built.

- **restic (0.19.1) and rclone (1.75.2) run as pinned images** in a Compose
  `backup` profile, not as host packages, so their versions are reviewed in the
  repository and CI runs what production runs.
- **Hand-written systemd units in `flake.nix`**, not nixpkgs'
  `services.restic.backups`, which runs prune and check inside every backup.
- **One lock** (`flock`) for deploy, backup, prune and the drills.
- **The check restores the dump it checks**, into a scratch database, every
  run.
