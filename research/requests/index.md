# Research: Requests

The user's feature requests, recorded as written before research or planning
begins, so a compaction can't lose a detail. Each batch is a dated folder:

- the message verbatim (`as-written.md`);
- one file per request, splitting it into numbered requirements, each paired
  with the user's own words;
- the questions research or planning must answer.

These are inputs, not decisions. When a request is researched, the decision
goes in the category it belongs to (e.g. `security-privacy/`). When it is
planned, the work goes in `features/`. The batch's index links both and
tracks progress.
